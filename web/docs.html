Quick start

1. Sign in on the dashboard with Google, create an API (give it a name) and copy its public key (pk_...). Add your site's address to the API's allowed origins. Each API has its own lobbies, separate from all your other APIs.

2. Add the SDK. It is one ES module with no dependencies: copy lobbi.js into your project (an npm package named lobbi is planned).

import { Lobbi } from './lobbi.js';

const net = await Lobbi.connect({ key: 'pk_...', url: 'wss://api.example.com' });
const lobby = await net.joinOrCreate({ name: 'room-1', max: 8 });

lobby.on('message', (from, data) => { /* apply game state */ });
lobby.on('closed', (reason) => { /* back to the menu */ });
lobby.send(JSON.stringify({ x: 1, y: 2 }));

Concepts

  • Host. The player who creates a lobby. The host runs the game and holds a WebRTC connection to every player.
  • Star topology. Players send to the host; the host sends to one player or to everyone. Players do not connect to each other.
  • Lobby closes with the host. If the host leaves or disconnects, every player gets closed. A brief network blip is tolerated for about 10 seconds. Host migration is not built yet.
  • Channels. fast is unreliable and unordered (positions, inputs), limited to 16 KB per message. safe is reliable and ordered (chat, events); messages up to 8 MB are split and reassembled for you.
  • Adaptive cap. Lobbi measures the host's upload speed and watches tick time, then raises or lowers how many players new joins can admit. It never removes players already in.

Connecting

const net = await Lobbi.connect({ key, url, perPlayerKbps?, tickBudgetMs? });
OptionMeaning
keyYour game's public key. Safe to ship in client code; it only works from the origins you allow.
urlLobbi address, for example wss://api.example.com.
perPlayerKbpsExpected bandwidth per player. Sizes the adaptive cap. Default 64.
tickBudgetMsYour simulation tick budget (1000 / tick rate). Default 50.

Events on net: disconnected, reconnecting, reconnected (with { resumed }), offline and error. Call net.close() to disconnect.

Lobbies

CallWhat it does
net.joinOrCreate(opts)Joins the fullest open lobby with that name, or creates it and makes you the host.
net.create(opts)Creates a lobby. Options: name, max, public, password, meta (small JSON object, 1 KB), perPlayerKbps.
net.join(code, { password })Joins by the 5-character code.
net.list({ name }, cursor)Public lobbies with free slots, 50 per page: { items, cursor }.
lobby.leave()Leaves. If you are the host the lobby closes.
lobby.kick(id) / lobby.setMeta(obj)Host only.

Useful properties: lobby.code, id, hostId, isHost, max (current admission cap), members, connected, meta.

Messages

lobby.send(data, { to?, channel? });   // string, ArrayBuffer or typed array
lobby.broadcast(data, { channel?, except? });
if (lobby.isHost) lobby.reportTick(ms);  // call once per simulation tick

Players always send to the host. The host sends to to, or to everyone when it is omitted. send returns false if nothing was sent (not connected yet, or a fast packet dropped because the queue was full). lobby.stats() lists each connection with relayed, rttMs and queue size.

Lobby events

EventWhen
playerConnected({ id, relayed })Host: a player's connection is ready.
connected({ relayed })Player: your connection to the host is ready.
playerJoined(id) / playerLeft(id, reason)Roster changes, for everyone.

cap(max) / meta(obj)The admission cap or lobby metadata changed.
closed(reason)The lobby is over. Reasons: host-left, host-lost, kicked, p2p-failed, connect-timeout, connection-lost, server-restart, left.

Errors

Calls reject with a LobbiError that has a code.

CodeMeaning
connect_failedWrong address or key, or your site's origin is not allowed.
not_found, full, bad_passwordJoin problems.
lobby_limit, account_lobby_limit, ip_lobby_limit, create_rateA limit was reached (game, plan, network or creation rate).
rate_limitedToo many messages to the server.
too_bigA fast message over 16 KB, or any message over 8 MB.

Connections and relay

Players first try to connect directly to the host. The SDK and the browser handle this for you; there is nothing to configure.

  • Direct. The usual case. Game data goes straight between players and costs nothing.
  • Relay. Used only when a network blocks direct connections. The relay carries the game data, so it is limited: Lobbi grants relay access only to players inside a lobby with at least two members, and each API has a total relay allowance.

The connection row in the demo shows Direct or Relayed. Expect most connections to be direct.

Keys, APIs and limits

  • Each API is independent. It has its own public key, tier and lobbies. Lobby codes, lists and quick match never cross from one API to another, even on the same account.
  • Add the exact origins that may use the key (for example https://mygame.example.com; no paths, no wildcards). Rotate the key from the dashboard if it leaks.
  • Tiers. Every API has a tier; 0 is Free. Free allows 8 players per lobby, 25 open lobbies and 150 simultaneous connections per API, and 3 APIs per account. See Tiers.
  • Connection setup is unlimited. Only the relay is limited, by a total allowance per API (3,000 relay joins on Free), not a daily one. When it is used up, players who can connect directly still can; others cannot join.
  • Origin checks stop other websites, not scripts. Treat the key as public and rely on the limits.
